## 2. 스토리 — 직급 시스템

플레이어의 성장 동기(Motivation)를 **자전거샵 직급**으로 표현합니다.

```text
알바생 → 견습공 → 기술자(판독 불확실) → Master
```

- 직급과 별개로 **레벨** 시스템 병행 (화면 하단 `Status L-100` 표기 — 레벨 상한 100으로 추정, 확인 필요)
- 기존 콘셉트([GAME_CONCEPT.md](../game-design/GAME_CONCEPT.md))의 "아르바이트하며 드림 바이크를 향해 성장"하는 판타지를 직급 승급으로 구체화하는 방향

## 3. 투어(Tour) — 보상 시스템

투어는 장기 보상·진행 시스템입니다.

- **일차(Day) 단위 진행**: Day 1 → 2 → 3 → 4 → …
- 일차별로 머지(주문 처리)를 완료하면 **사진(그림) 조각이 완성**되는 구조
- 사진이 모여 하나의 **투어 챕터(Tour Chapter)** 를 이루는 형태
- 챕터 후반에 **Boss** 요소 등장 (Boss 주문 또는 Boss 사진 — 규칙 미확정)
- 화이트보드 수치 메모: `30日`, `200대` (한 투어 분량 후보로 추정 — 의미 확인 필요)

## 4. 이벤트 — 주문자 유형

주문자(고객)의 유형에 따라 보상이 달라지는 이벤트 구조입니다.

| 주문자 유형 | 보상 |
|---|---|
| 일반 고객 | 기본 급여 |
| 선수 | 추가 금액 |
| 관계자 | 추가 금액 |

기존 설계서의 [주문 보상 공식](../game-design/MERGE_GAME_SYSTEM_DESIGN.md#91-주문-보상)에
"주문자 보너스" 항목을 추가하는 방향으로 검토합니다.

## 5. 스킬 · 머니 — 드림 바이크 업그레이드

```text
Skill + Money → 자기 자전거(드림 바이크) Upgrade
```

- 주문 처리로 얻은 **급여(Money)** 와 성장한 **스킬(Skill)** 로 자신의 자전거를 업그레이드
- [GAME_CONCEPT.md](../game-design/GAME_CONCEPT.md) 핵심 게임 루프 8단계
  ("급여로 자신의 드림 바이크를 성장시킨다")를 구체화하는 방향
- Skill의 정체(패시브 능력치인지, 액티브 스킬인지)는 미확정

## 6. 화면 구조

메인 화면 구조 스케치를 잡았습니다. 상세 내용은
[화면 구조 초안](../game-design/SCREEN_STRUCTURE.md) 문서를 기준으로 합니다.

요약:

- 상단: 스태미너, 획득 코인, 투어 진입, 이벤트 알림, 리더 순위(랭킹)
- 중앙: 주문 자전거 슬롯(대기 주문 목록) + 머지 보드
- 하단: 직급(알바생) / Status (레벨) / 아이콘 메뉴

다음 회의 안건 또는 Issue로 처리합니다.

- [ ] 직급 3단계 명칭 확정 (알바생 → 견습공 → **?** → Master)
- [ ] `30日`, `200대` 메모의 의미 (한 투어 분량인지, 전체 콘텐츠 볼륨인지)
- [ ] Boss 규칙 (Boss 주문인지, 챕터 완성 보상 사진인지)
- [ ] 스태미너 소모·회복 규칙 (주문 시작 시 소모?)
- [ ] `Status L-100`의 의미 (레벨 상한 100 여부)
- [ ] 하단 우측 아이콘의 기능 (하트 모양 — 컬렉션? 상점?)
- [ ] 외부 리소스 검토 ③번 항목
