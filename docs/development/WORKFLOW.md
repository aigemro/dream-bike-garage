# Collaboration Workflow

1. GitHub Issue에 목표와 완료 조건을 작성합니다.
2. `feat/*`, `design/*`, `fix/*`, `chore/*` 브랜치를 만듭니다.
3. 작은 단위로 커밋하고 Pull Request를 엽니다.
4. 기획자는 기획 의도와 사용자 경험을 확인하고, 설계·개발자는 기술 구조·화면·데이터·테스트 결과를 확인합니다.
5. PR 본문에 `Closes #이슈번호`를 넣고 `main`에 병합합니다.
6. CI 성공 후 GitHub Pages가 자동 배포됩니다.

## 역할

### 기획자

- 게임 콘셉트와 목표 사용자 경험 정의
- 핵심 게임 루프, 규칙, 콘텐츠와 밸런스 방향 수립
- 화면 흐름과 기능 요구사항 작성
- 우선순위와 완료 기준 협의
- 구현 결과가 기획 의도에 맞는지 검토
- 기획 문서와 변경 사항 관리

주요 작업 영역: `docs/game-design`, GitHub Issue, 기획 관련 Wiki 및 리뷰

### 설계·개발자

- 기획 내용을 시스템, 화면, 데이터 구조로 구체화
- 기술 아키텍처와 구현 방안 설계
- 게임 기능, UI, 데이터, 테스트 코드 구현
- GitHub Actions와 GitHub Pages 등 개발·배포 환경 관리
- 개발 중 확인된 제약, 누락 사항과 추가 결정 필요 항목 공유
- 구현 결과와 설계 문서 간 일치 여부 확인

주요 작업 영역: `src`, `src/data`, `tests`, `.github/workflows`, `docs/development`, `prompts`

### 공통

- GitHub Issue 우선순위와 일정 협의
- Pull Request 및 결과물 리뷰
- 주요 의사결정과 변경 이유 기록
- 기획 변경 사항과 개발 영향도 공유

## 협업 원칙

- 기획자는 무엇을 만들고 왜 필요한지를 정의합니다.
- 설계·개발자는 이를 어떻게 구현할지 구체화하고 실제 결과물로 만듭니다.
- 구현 중 기획 판단이 필요한 항목은 임의로 확정하지 않고 Issue를 통해 공유합니다.
- 기획 변경 시 관련 설계, 코드, 테스트와 문서를 함께 갱신합니다.

## Project 보드

Backlog → Ready → In Progress → Review → Done

보류 작업은 Hold 상태로 분리합니다.
