### 출시일 협의 필요 🟡

**출시 목표 시점이 "2026년 11월"이라는 점만 합의되어 있고, 11월 안의 구체적인 날짜는 아직 협의되지 않았습니다.**

이 문서의 11월 날짜는 설계·개발자가 작성한 **잠정안**입니다. 근거는 다음과 같습니다.

| 잠정일 | 근거 |
|---|---|
| 11/2(월) 심사 제출 | 10/29 회의에서 RC를 승인한 직후 첫 영업일 |
| 11/19(목) 정식 출시 | 심사 반려를 가정한 2주 대응 기간 확보 + 회의일에 Go/No-Go와 출시를 함께 처리 |
| 11/26(목) 출시 리뷰 | 출시 후 1주간 초기 지표·이슈를 관찰한 뒤 리뷰 |
| 11/17(월) 코드 동결 | 출시 2영업일 전 |

#### 협의해서 확정할 항목

1. **정식 출시일** — 11/19 유지 여부. 조정 시 심사 대응 기간이 함께 변합니다.
   - 앞당김(예: 11/12): 심사 대응 기간이 1주로 줄어 반려 시 11월 출시가 위험합니다. 심사 제출을 10월 말로 앞당기는 전제가 필요합니다.
   - 늦춤(예: 11/26): 대응 기간은 3주로 늘지만 출시 후 관찰 기간이 11월 안에 남지 않아 M7 리뷰가 12월로 넘어갑니다.
2. **심사 제출일** — 11/2 유지 여부. 앱인토스 심사 소요 기간을 확인한 뒤 확정합니다.
3. **출시 시각과 담당** — 출시 당일 실행 담당과 확인 절차.
4. **출시 연기 판단 기준** — 어떤 조건이면 11월 출시를 포기하고 12월로 넘기는지.

#### 확정 절차

- **10/29 회의(M4 RC 승인)에서 출시일을 확정**합니다. 그 전까지는 잠정일로 취급합니다.
- 다만 앱인토스 심사 소요 기간은 그보다 먼저 확인해야 하므로, **10/8 회의에서 심사 기간을 근거로 출시일 후보를 1차 협의**합니다.
- 출시일이 확정되면 이 문서의 2·7·8절과 GitHub Milestone을 같은 날 갱신하고 🟡 표시를 제거합니다.

> **10월까지의 일정(M0~M4)은 출시일 협의 결과와 무관하게 그대로 진행합니다.** 출시일 미확정을 이유로 8~10월 작업을 늦추지 않습니다.

## 3. 일정 변경 규칙

지연이 발생하면 **날짜를 미루지 않고 범위를 줄입니다.** 판단 순서는 다음과 같습니다.

1. 해당 스프린트의 "이번 주에 뺄 수 있는 것"을 먼저 제거한다.
2. 그래도 부족하면 MVP 제외 후보(6절)로 이동시킨다.
3. 위 두 방법으로 해결되지 않는 경우에만 목요일 회의에서 마일스톤 날짜 조정을 논의한다.
4. 마일스톤 날짜를 조정하면 이 문서와 GitHub Milestone을 같은 날 갱신한다.

M5(심사 제출)와 M6(출시) 사이에는 심사 반려를 가정한 **2주 대응 기간**이 들어 있습니다. 이 기간은 신규 작업에 사용하지 않습니다.

현재 문서 간 불일치와 미확정 항목이 남아 있습니다. 아래 항목을 8월 안에 모두 닫습니다.

**(A) 문서 간 불일치 해소** — 같은 항목이 문서마다 다르게 적혀 있습니다.

| 항목 | [MVP.md](../game-design/MVP.md) | [시스템 설계서](../game-design/MERGE_GAME_SYSTEM_DESIGN.md) | 확정 필요 |

**(B) 시스템 설계서 14절 미확정 항목**

- 주문용 에너지 또는 코인 소비 방식

**(C) 개발 착수에 필요한 산출물**

- 주문 3종의 구체 스펙(필요 부품 종류·레벨·제한 시간·보상)

- 밸런스 초기값 확정(시스템 설계서 12절 표를 확정값으로 전환)
- 에셋 사용 원칙(가상 브랜드 사용, 출처 확인된 에셋만 사용)

## 9. 출시 범위

### 포함

- 머지 보드와 부품 이동·머지
- 부품 종류와 레벨 표시
- 온라인 부품 주문으로 부품 생성
- 주문 카드와 진행률 표시, 주문 3종

- 납품과 급여·시간 보너스
- 완성차 컬렉션
- 드림 바이크 성장(최소 1~2단계)
- 소프트 타이머
- localStorage 저장과 재실행 복구
- 모바일 세로 화면과 터치 조작
- 앱인토스 SDK 기본 연동
- 기본 효과음, 완성 연출, 오류 피드백
- 첫 실행 안내

### 제외

- 실제 자전거 브랜드와 로고 (라이선스 협의 전까지 가상 브랜드 사용)
- 매치3 재료 수급, 레이스, 샵 경영, 직원 관리
- 광고와 인앱 결제
- 스태미너와 에너지 소비 구조 (8월 결정 결과에 따름)
- 복잡한 성장 트리와 시즌 운영
- 서버 계정 동기화
- 여러 주문 동시 처리
- 고급 분석과 LiveOps

### MVP 제외 후보 (지연 시 먼저 제거)

일정이 밀릴 경우 아래 순서로 범위를 줄입니다.

1. 연속 머지 콤보
2. 긴급 주문 유형
3. 품질 보너스(상위 부품 장착 보너스)
4. 드림 바이크 성장 2단계 이후
5. 완성차 컬렉션 종류 축소(5종 → 3종)
6. 사운드 축소(효과음 최소 세트만 유지)

| 에셋 라이선스 문제 | 출시 불가 | 가상 브랜드와 출처 확인된 에셋만 사용, 10월 말 전수 점검 |
| 로그인 연동 지연 | 핵심 루프 일정 영향 | 출시 필수가 아니면 게스트 플레이·로컬 저장 우선 |
| 재미가 검증되지 않음 | 출시 가치 하락 | 10/15 플레이테스트를 밸런스 조정 근거로 사용 |

## 12. 출시 완료 기준

다음 조건을 모두 만족하면 11월 출시가 완료된 것으로 판단합니다.

- 실제 앱인토스 환경에서 게임이 실행된다.
- 신규 사용자가 안내를 따라 첫 주문을 완료할 수 있다.
- 부품 생성 → 머지 → 조립 → 납품 → 급여 → 컬렉션 → 드림 바이크 성장이 끊김 없이 연결된다.
- 재실행 후 진행 상태가 복구된다.
- 치명적 오류와 진행 불가 상태가 없다.
- 사용한 이미지·사운드·문구의 권리와 출처를 확인했다.
- 출시 버전과 알려진 제한 사항을 GitHub 릴리스에 기록했다.
- `npm test`와 `npm run build`가 CI에서 통과한다.
