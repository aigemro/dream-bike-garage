# 주간 진행 공유 회의 운영

Dream Bike Garage는 **매주 목요일 진행 공유 회의**를 일정 관리의 축으로 운영합니다.
전체 일정과 각 회의에서 결정할 내용은 [2026년 11월 출시 계획](RELEASE_PLAN_2026_11.md)을 기준으로 합니다.

## 1. 기본 정보

| 항목 | 내용 |
|---|---|
| 주기 | 매주 목요일 (공휴일과 겹치면 직전 수요일로 이동) |
| 참석 | 기획자 임성민 위원, 설계·개발자 김태훈 프로 |
| 권장 시간 | 60분 |
| 스프린트 | 회의 직후 시작 → 다음 수요일 종료 (7일) |

회의는 **진행 보고 자리가 아니라 결정 자리**입니다. 진행 상황은 회의 전에 공유하고, 회의 시간은 결정이 필요한 항목에 사용합니다.

## 2. 회의 전 준비 (수요일까지)

### 설계·개발자

- 플레이 가능한 빌드를 GitHub Pages에 배포하고 링크 공유
- 지난 스프린트에서 완료한 Issue와 미완료 Issue 정리
- **기획 결정이 필요한 항목**을 Issue로 등록하고 목록 공유
- 구현 중 확인된 제약과 일정 영향도 정리

### 기획자

- 배포된 빌드를 미리 플레이하고 의도와 다른 부분 메모
- 이번 주에 결정할 기획 항목의 안(案) 준비
- 다음 스프린트에 필요한 기획 산출물 확인

> 배포 링크가 수요일까지 공유되지 않으면 그 주 회의는 **플레이 검토 없이 결정 안건만** 다룹니다. 회의 시간에 처음 플레이하며 시간을 소모하지 않습니다.

## 3. 회의 진행 순서 (60분)

| 시간 | 순서 | 내용 |
|---|---|---|
| 10분 | 지난 스프린트 결과 | 완료·미완료 항목, 미완료 사유 |
| 15분 | 플레이 검토 | 기획자가 직접 플레이하고 의도와의 차이 확인 |
| 20분 | **기획 결정** | 이번 주 결정 항목을 하나씩 닫기 (미결정 항목을 남기지 않음) |
| 10분 | 다음 스프린트 계획 | 작업 범위 확정, 담당 확인 |
| 5분 | 위험과 일정 | 마일스톤 영향, 범위 축소 필요 여부 |

### 결정 원칙

- 결정 항목은 **결정 / 다음 주로 이월 / MVP 제외** 세 가지 중 하나로 반드시 닫습니다. "더 생각해보기"로 남기지 않습니다.
- 이월은 1회까지만 허용합니다. 두 번째 회의까지 결정되지 않으면 **MVP 제외**로 처리합니다.
- 마일스톤 게이트 회의에서는 승인 여부를 그 자리에서 판단합니다. 승인하지 않으면 범위를 줄이고 날짜를 유지합니다.

### 출시일 협의 안건 (예정)

정식 출시일은 아직 확정되지 않았습니다. 아래 두 회의에 고정 안건으로 올립니다.

| 회의 | 안건 |
|---|---|
| 10/8 | 앱인토스 심사 소요 기간 확인 결과 공유, 출시일 후보 1차 협의 |
| 10/29 | **정식 출시일 확정** (출시 시각·담당·연기 판단 기준 포함) |

확정 즉시 [RELEASE_PLAN_2026_11.md](RELEASE_PLAN_2026_11.md)의 11월 날짜와 GitHub Milestone을 갱신합니다.

## 4. 회의 후 처리 (48시간 안에)

| 담당 | 작업 |
|---|---|
| 개발자 | 결정 사항을 관련 문서에 반영 (`docs/game-design`, `docs/development`) |
| 개발자 | 다음 스프린트 Issue 등록·갱신, Milestone 연결, Project 보드 이동 |
| 개발자 | 일정 변경이 있으면 [RELEASE_PLAN_2026_11.md](RELEASE_PLAN_2026_11.md) 갱신 |
| 공통 | 회의 기록을 Notion 프로젝트 진행 대시보드에 남기기 |

문서에 반영되지 않은 구두 결정은 **결정되지 않은 것으로 간주**합니다.

## 6. 회의 없이 처리하는 것

아래 항목은 목요일까지 기다리지 않고 그때그때 처리합니다.

- 진행 불가 버그 → 즉시 공유 후 수정
- 명백한 오탈자·문구 수정
- 리팩터링, 테스트 추가, CI 설정
- 이미 결정된 기획의 구현 방식 선택

반대로 **기획 의도가 걸린 판단은 임의로 확정하지 않고** Issue로 올려 회의 안건으로 넘깁니다([WORKFLOW.md](WORKFLOW.md) 협업 원칙).
