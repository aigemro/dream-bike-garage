> 문서 상태: 검토용 초안 (8/13 M0 회의 안건)  
> 작성일: 2026-08-08  
> 일정·게이트 기준: [2026년 11월 출시 계획](RELEASE_PLAN_2026_11.md) — **날짜와 게이트는 일정 문서가, 작업 내용은 이 문서가 기준입니다.**  
> 설계 근거: [레퍼런스 게임 분석과 MVP 적용 제안](../planning/REFERENCE_GAMES.md)

## 1. 계획의 원칙

1. **레퍼런스가 검증한 것은 그대로 쓴다.** 주문 기반 머지-2 장르(Travel Town, Love & Pies, Merge Mansion)가 이미 검증한 구조 — 2-to-1 머지, 상시 노출 주문 카드, 카테고리형 생성기, 잠금 칸 보드 온보딩 — 는 재발명하지 않고 채택합니다.
2. **차별화 지점만 실험한다.** 레퍼런스와 다르게 가는 것(소프트 타이머와 시간 vs 품질 선택, 에너지 없는 주문 단위 세션, 조립대 장착 연출)은 Lab에서 8월 안에 검증하고, 검증 실패 시 레퍼런스 표준으로 후퇴합니다.
3. **도메인 우선 구현.** 모든 규칙은 `src/domain`(Phaser 비의존)에 Vitest 테스트와 함께 먼저 구현하고, Scene은 그 결과를 표현만 합니다. 밸런스 수치는 `src/data`의 명시적 타입으로 분리해 기획자가 검토할 수 있게 유지합니다.
4. **스프린트 끝은 항상 플레이 가능.** 각 스프린트 종료 시 GitHub Pages에 배포하고, 목요일 회의에서 기획자가 직접 플레이합니다 ([WEEKLY_SYNC.md](WEEKLY_SYNC.md)).

## 3. 스프린트별 작업 계획 (S4~S7)

일정 문서의 스프린트 경계를 따릅니다: S4 9/3~9/9 · S5 9/10~9/16 · S6 9/17~9/22 · S7 9/23~9/30.

### S4 (9/3~9/9): 주문 → 생성 → 머지

목표: 주문을 보고 필요한 부품을 머지로 목표 레벨까지 만들 수 있다.

| 영역 | 작업 | 레퍼런스 근거 |
|---|---|---|
| data | 주문 3종·부품·레벨·보상 스키마 확정 및 `src/data` 이관 | — |
| domain | 확정 보드 크기·잠금 칸 규칙, 카테고리 선택형 부품 생성 규칙, 머지·이동·차단 규칙 갱신 + 테스트 | Love & Pies 잠금 칸, 설계서 5~6장 |
| scene | 주문 카드 UI (자전거 이미지·필요 부품·요구 레벨·진행률 상시 노출) | Travel Town 주문 카드 |
| scene | 온라인 부품 주문 UI (Lab 채택안 반영: 카테고리 버튼 + 채택된 생성 연출) | Lab Parts Supply 채택안 |
| scene | 잘못된 머지·배치 피드백, 부품 종류·레벨 표시 | 장르 공통 |
| 공통 | 주문 진행률 실시간 반영 | — |

### S5 (9/10~9/16): 조립 → 납품 → 보상

목표: 주문 1건을 시작부터 급여 획득까지 완주할 수 있다.

| 영역 | 작업 | 레퍼런스 근거 |
|---|---|---|
| domain | 조립대 슬롯 장착·회수 규칙, 완성 판정, 급여·보너스 계산 + 테스트 | Lab 주문·조립 채택안 (#17/#18) |
| domain | 소프트 타이머 (채택 시): 권장 시간·시간 보너스·실패 없음 원칙 | 설계서 §7~8, Lab 보상 C |
| scene | 부품 장착 시 자전거가 단계별로 완성되는 연출 | Assemble with Care, 설계서 §8 |
| scene | 납품 연출, 급여·보너스 결과 화면, 코인 누적 표시 | Travel Town 납품 리듬 |

### S6 (9/17~9/22): 컬렉션·성장·저장

목표: 새로고침 후에도 진행 상태가 복구된다.

| 영역 | 작업 | 레퍼런스 근거 |
|---|---|---|
| domain | 컬렉션 해금·드림 바이크 성장 규칙 + 테스트 | Lab 수집 채택안 (#12/#14/#60) |
| scene | 컬렉션 화면, 드림 바이크 성장 화면(급여 투자) | 수집이 메타 역할 (레퍼런스 §2) |
| platform | localStorage 저장·복구, 저장 데이터 버전 관리, 새 게임 초기화 | Lab 플랫폼 #3 |

### S7 (9/23~9/30): 전체 루프 연결과 웹 알파

목표(M2): 신규 사용자가 안내를 따라 주문 3종을 완료하고 드림 바이크를 1단계 성장시킬 수 있다.

| 영역 | 작업 | 레퍼런스 근거 |
|---|---|---|
| 공통 | 주문 3종 연속 진행, 주문 간 전환(보드 유지 규칙은 8월 결정) | — |
| scene | 첫 실행 안내: 잠금 칸 해제를 온보딩 장치로 사용 (채택 시) | Love & Pies 온보딩 |
| platform | 모바일 세로 레이아웃·터치 1차 대응 (Lab 입력·반응형 채택안) | Lab #33, #4 |
| data | 주문 3종 밸런스 1차 조정 | 설계서 §12 초기값 |
| 공통 | 기본 효과음·오류 피드백, 웹 알파 Pages 배포 | — |

## 5. 범위 축소 규칙

일정 지연 시 [2026년 11월 출시 계획 §9](RELEASE_PLAN_2026_11.md)의 MVP 제외 후보 순서를 따릅니다. 이 계획에서 스프린트별 최소 방어선은 다음과 같습니다.

- S4: 주문 카드 + 머지까지는 포기하지 않음 (생성 연출은 즉시 버튼으로 후퇴 가능)
- S5: 조립·납품·기본 급여까지는 포기하지 않음 (타이머·품질 보너스 제외 가능)
- S6: localStorage 저장·복구는 포기하지 않음 (드림 바이크 성장은 1단계로 축소 가능)
- S7: 주문 3종 완주와 첫 실행 안내는 포기하지 않음 (사운드 최소화 가능)
