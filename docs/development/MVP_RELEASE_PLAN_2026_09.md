# 2026년 9월 MVP·앱인토스 출시 계획

## 1. 목적

2026년 8월 5일을 기준으로 Dream Bike Garage의 현재 구현과 Lab 검증 결과를 연결하여, **2026년 9월 안에 핵심 게임 루프가 끝까지 동작하는 출시형 MVP를 완성하고 앱인토스 출시를 경험하는 것**을 목표로 합니다.

이 계획은 완성형 게임이 아니라 다음 흐름을 실제 사용자가 처음부터 끝까지 플레이할 수 있는 버전을 대상으로 합니다.

> 고객 주문 → 부품 생성 → 머지 → 자전거 조립 → 주문 완료 → 급여 획득 → 자전거 수집

## 2. 현재 출발점

프로젝트는 처음부터 개발을 시작하는 상태가 아닙니다.

- Phaser + Vite 기반 실행 환경
- GitHub Actions와 GitHub Pages 배포 구조
- 플레이 가능한 머지 코어
- 메인 프로젝트와 Lab의 역할 분리
- 머지·주문·조립·입력·반응형 화면을 비교하는 Lab 트랙
- 게임 콘셉트와 기본 MVP 문서
- 앱인토스 SDK·로그인 연동 검증 준비

따라서 8월 전체를 프로토타입 제작에 사용하지 않고, **8월 16일까지 핵심 방안을 선택한 뒤 메인 게임 통합을 시작**합니다.

## 3. 출시형 MVP 범위

### 포함 목표

- 머지 보드
- 프레임·휠셋·구동계·핸들바 중심의 부품 구성
- 동일 종류·동일 단계 부품의 2-to-1 머지
- 부품 레벨 표시
- 시각적인 주문 카드와 주문 진행률
- 주문 3종
- 부품 준비 → 조립 → 납품 → 급여 획득
- 간단한 자전거 컬렉션 3~5종
- 소프트 타이머와 시간 보너스
- 로컬 저장과 재실행 복구
- 모바일 세로 화면과 터치 조작
- 앱인토스 SDK 기본 연동과 실제 테스트
- 기본 효과음, 완성 연출, 오류 피드백

보드 크기, 부품 종류 수, 조립 방식은 기존 [MVP 범위](../game-design/MVP.md)와 Lab 결과가 다를 수 있으므로 8월 13일까지 비교 후 최종 확정합니다.

### 제외 범위

- 실제 자전거 브랜드와 로고
- 매치3, 레이스, 샵 경영, 직원 관리
- 광고와 인앱 결제
- 복잡한 성장 트리와 시즌 운영
- 서버 계정 동기화
- 여러 주문의 동시 처리
- 모든 Lab 트랙의 완전한 구현
- 고급 분석과 LiveOps

실제 브랜드는 라이선스 협의 전까지 사용하지 않고 MVP에서는 가상 브랜드와 자체 제작 에셋을 사용합니다.

## 4. 추진 원칙

1. Lab은 기술 대안을 비교하고, 메인 프로젝트는 채택 결정과 최종 적용을 담당합니다.
2. 8월 16일 이후에는 출시 필수 문제를 제외한 새 프로토타입을 추가하지 않습니다.
3. 8월 27일 알파 승인 이후 신규 기능을 추가하지 않습니다.
4. 9월 중순 이후는 기능 개발이 아니라 검토 대응과 안정화 기간으로 사용합니다.
5. 앱인토스 등록과 정책 검토는 게임 개발 완료를 기다리지 않고 병행합니다.
6. 로그인 연동이 출시 필수가 아니라면 게스트 플레이와 로컬 저장을 우선합니다.

자세한 저장소 운영 기준은 [메인 프로젝트와 Lab 운영 경계](PROJECT_BOUNDARY.md)를 따릅니다.

## 6. 주차별 실행 계획

### 1주차: 8월 5일~9일 — 범위 확정

- 주문 3종과 주문별 필요 부품·목표 레벨 결정
- 한 판의 플레이 흐름과 완료 조건 확정
- 보드 기본 크기와 부품 종류 수 검토
- MVP 화면 목록 확정
- 가상 자전거 데이터와 에셋 사용 원칙 확정
- 앱인토스 워크스페이스·앱 정보 등록
- SDK와 테스트 환경 준비
- 9월 출시 제외 기능 확정

완료 기준은 기획자와 설계·개발자가 MVP 포함·제외 범위에 합의하고 관련 이슈의 우선순위가 정리된 상태입니다.

### 2주차: 8월 10일~16일 — Lab 방안 선택

- 머지 Prototype A/B/C를 동일 조건으로 비교
- 주문 표시 방식을 비교하고 한눈에 목표를 파악할 수 있는지 확인
- 드래그와 탭 입력 비교
- 데스크톱·모바일 화면 배치 확인
- 보드 크기 변경 시 버튼·텍스트·부품이 겹치지 않는지 확인
- 다칸 부품과 조립 규칙 검토
- 조립 슬롯 직접 배치와 자동 조립 비교
- 메인 프로젝트의 채택 이슈에 결과와 근거 기록

우선 검토안은 자유 보드와 주문 가이드의 조합, 드래그 기본·탭 보조, 직접 슬롯 배치, 기본 급여와 시간 보너스, 단순 도감형 수집입니다. 이는 확정안이 아니며 8월 13일 회의에서 결정합니다.

### 3주차: 8월 17일~23일 — 첫 주문 완주

- 주문 자전거와 필요 부품을 이미지 형태로 표시
- 온라인 주문 방식의 부품 생성
- 이동·회전·머지 처리
- 부품 종류와 레벨을 명확히 표시
- 주문 진행률 실시간 반영
- 잘못된 머지와 배치 피드백
- 조립대 슬롯과 장착
- 첫 주문을 시작부터 조립까지 플레이 가능하게 구성

완료 기준은 한 주문을 처음부터 조립 단계까지 중단 없이 진행할 수 있는 상태입니다.

### 4주차: 8월 24일~30일 — 웹 알파 MVP

- 주문 완료와 납품 연출
- 기본 급여·시간 보너스 계산
- 코인 누적
- 간단한 자전거 구매 또는 해금
- 컬렉션 화면
- localStorage 저장
- 새로고침과 재실행 복구
- 튜토리얼성 안내
- 주문 3종 밸런스 조정
- GitHub Pages 알파 배포

8월 27일 회의에서 알파 버전을 승인하고 신규 기능 추가를 종료합니다.

### 5주차: 8월 31일~9월 6일 — 앱인토스 통합

- 웹 프로젝트에 앱인토스 SDK 적용
- 일반 브라우저 mock과 앱인토스 adapter 분리
- 앱 번들 생성과 테스트 업로드
- 테스트 QR을 통한 실제 토스 앱 실행
- 뒤로가기·백그라운드·복귀 처리
- Safe Area와 100dvh 대응
- Android 기기별 터치·오디오 확인
- 로그인 연동 검증

완료 기준은 실제 토스 앱 테스트 환경에서 첫 주문을 진행할 수 있는 상태입니다.

### 6주차: 9월 7일~13일 — 출시 후보

- 첫 실행부터 주문 완료까지 전체 QA
- 치명적 버그 제거
- 앱 설명·아이콘·대표 이미지·이용 안내 준비
- 개인정보·로그인·저장 범위 점검
- 저작권이 불명확한 이미지와 사운드 제거
- 로딩 성능과 번들 크기 확인
- 최종 번들 업로드
- 늦어도 9월 11일까지 검토 요청

### 7주차: 9월 14일~20일 — 검토 대응

- 검토 의견을 정책·문구·UI·오류로 분류
- 수정 후 실제 토스 앱에서 재검증
- 수정 버전 재업로드
- 데이터 초기화와 업데이트 시나리오 확인
- 출시 후 긴급 롤백 기준 작성

### 8주차: 9월 21일~27일 — 출시

- 최종 Go/No-Go 확인
- MVP 정식 출시
- 실제 출시 진입 경로 확인
- 첫 주문 완료 가능 여부 확인
- 오류와 이탈 구간 기록
- GitHub 출시 태그와 릴리스 노트 작성
- 출시 이후 개선 사항을 별도 백로그로 분리

9월 28일~30일은 심사 지연과 긴급 수정에 사용하는 예비 기간입니다.

## 9. 주요 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| Lab 실험이 계속 증가 | 메인 통합 지연 | 8월 16일 이후 새 실험 제한 |
| 기획 범위 증가 | 기능 동결 실패 | 포함·제외 목록을 변경 기준으로 사용 |
| 웹과 앱인토스 환경 차이 | 출시 직전 오류 | SDK adapter 분리와 실제 기기 조기 검증 |
| 심사·검토 지연 | 9월 출시 실패 | 9월 11일까지 검토 요청, 9월 말 예비 기간 확보 |
| 에셋 라이선스 문제 | 출시 불가 또는 교체 비용 | 가상 브랜드와 출처가 확인된 에셋만 사용 |
| 화면 겹침과 작은 조작 영역 | 플레이 불가 | 보드 크기별 레이아웃과 모바일 터치 QA 수행 |
| 로그인 연동 지연 | 핵심 루프 일정 영향 | 필수가 아니면 게스트 플레이 우선 |

## 10. 출시 완료 기준

다음 조건을 모두 만족하면 9월 MVP 출시가 완료된 것으로 판단합니다.

- 실제 앱인토스 환경에서 게임이 실행됨
- 신규 사용자가 안내를 따라 첫 주문을 완료할 수 있음
- 부품 생성·머지·조립·납품·급여·수집 흐름이 연결됨
- 재실행 후 진행 상태가 복구됨
- 치명적 오류와 진행 불가 상태가 없음
- 사용한 이미지·사운드·문구의 권리와 출처를 확인함
- 출시 버전과 알려진 제한 사항을 GitHub에 기록함
