Lab 코드를 복사하지 않고, 채택한 규칙만 메인 구조(`src/domain` 순수 규칙 + Phaser 화면 + 컨트롤러)에 맞춰 다시 만들었습니다.

## 1. 바뀐 플레이 흐름

| 항목 | 이전(메인) | 지금 |
|---|---|---|
| 머지 코어 | 모양 부품(1~3칸) + 택배 4종 주문 + 자유 이동·회전 | **E안**: 부품 상자 1종, 가운데→바깥 순서로 자동 입고, 이동 금지, 상하좌우 2개 합성 |
| 하루(Day) | 주문 1건 납품 = 1 Day | **주문 3건 납품 = 하루 일정**, 하루가 끝나면 정산 |
| 정산 화면 | 주문마다 급여 봉투 | 하루 마감 때 오늘 수입 봉투 (급여는 납품 순간 바로 지급) |
| 플레이 제한 | 없음 | **알바 체력 하나**: 30, 상자당 1, 실제 10분당 1 회복 |
| 레이스 | Day 5마다 = 주문 5건마다 | Day 5마다 = 주문 약 15건마다 (참가비·상금은 #77에서 다시 정함) |

화면 흐름: 홈 PLAY → (첫 플레이 안내) → 작업대 → 주문 3건 납품 → 하루 정산 → 다음 영업 시작 또는 홈.
작업대의 `← 홈`이나 앱 전환으로 나가면 Day가 일시정지되고, 다시 들어오면 같은 Day를 이어서 합니다.

작업대는 한 행동(상자 열기·합성)에 납품을 1건만 확정하고, 납품하면 그 행동의 정리를 거기서 멈춥니다. 보드에 남은 부품은 화면이 납품 연출을 마치고 다음 주문 카드로 바꾼 뒤 `settleWorkbench`로 다음 주문에 장착하며, 4종이 차면 그 주문도 이어서 납품합니다(연출이 끝날 때마다 1건). 하루 마감 중에는 하지 않고 다음 영업일에 작업대로 들어올 때 이어 갑니다. 화면을 떠나 이 단계를 건너뛰어도 작업대 진입이나 다음 행동의 정리에서 똑같이 이어집니다. 이렇게 해서 급여·Day 집계가 1건씩 반영되고, 하루 마감 뒤 주문표가 밀리지 않으며, 다음 자전거 카드가 나오기 전에 이월 부품이 미리 장착돼 보이지 않습니다(2026-10-18 테스트 피드백).

주문의 단일 출처는 `src/data/level-design.ts`의 영업일 주문표입니다. `meta-progress.ts`의 `ORDER_METAS`는 이 주문표를 누적 주문 순번 순서로 펼친 것이고(위치 = 순번, 31일차부터는 21~30일차 반복), 작업대·홈·정산 화면이 모두 여기서 이름·카테고리·요구 레벨·보상을 읽습니다. 영업 d일차 = 순번 3(d−1)~3(d−1)+2이며, 저장 복구·다음 영업일 시작 때 작업대 순번을 Day 상태에 맞춥니다(`release-state.ts`의 `alignWorkbenchToDay`). 이전 게임 화면이 쓰는 `merge-prototype.ts`의 `ORDERS`는 더 이상 쓰지 않습니다.

| 규칙 | 값 |
|---|---|
| 보드 | 6×7 = 42칸 |

| 입고 순서 | 보드 가운데(2.5열, 3행)에서 가까운 칸부터, 같은 고리는 12시부터 시계 방향 |

| 합성 추천 | 선택 중이 아닐 때 빈칸 6칸 이하이거나 8초 무입력이면 먼저 합칠 쌍 1개를 노란 테두리로 반짝이고 이유를 안내. 아무 입력이나 하면 사라짐(강제 아님). 아래 7절 |

## 4. 납품과 Day 계약

Lab 메인 적용안 4.2절의 계약을 따릅니다.

1. 납품은 합성·상자 열기 시점에 도메인이 동기적으로 확정하고, 화면은 그 결과를 연출만 합니다.
2. 영업 중(`active`)이 아니면 상자 열기·합성·반품·되돌리기를 받지 않습니다.
3. 납품 1건마다 화면이 `onDelivered`를 정확히 한 번 호출하고, 컨트롤러가 코인·납품 수·이해도·오늘 통계를 한 번에 반영해 저장합니다.
4. 오늘 주문 수를 채우면 `closing`으로 넘어가 입력을 막고, 약 2초 연출 뒤 정산합니다. 그 사이 화면을 떠나면 다음 진입 때 정산합니다.

## 5. 저장

- 키는 기존 `dbg-lab-mvp-release-integration-v1`를 그대로 쓰고 `version: 4`로 올렸습니다. 작업대와 Day 상태가 같은 항목에 있어 납품 1건이 한 번의 저장으로 기록됩니다.
- 이전 저장(v2·v3)은 코인·납품 수·Day 번호·주문 순서·대회 기록·설정을 잇습니다. `autoPlacement`(이전 택배 자동 배치)는 더 이상 쓰지 않습니다.
- 복구 규칙: 영업 중이던 Day는 일시정지로, 정산까지 끝난 Day는 다음 Day 준비로 엽니다(급여 중복 없음). 마감 상태는 다음 진입 때 정산합니다.
- 저장소를 쓸 수 없는 환경에서도 메모리 진행으로 플레이를 이어갑니다.

## 7. 합성 추천 보조 (Lab #264 B안)

Lab [#264](https://github.com/aigemro/dream-bike-garage-lab/issues/264) B안의 규칙을 메인 작업대 규칙(`mergeParts`) 위에 다시 만들었습니다. Lab 코드는 복사하지 않았고, C안(막힘 구제·하루 1회 정리)은 이번 범위가 아닙니다.

| 항목 | 내용 |
|---|---|
| 추천 시점 | 선택 중이 아니고 합성할 쌍이 있을 때, ① 빈칸이 6칸 이하(`HINT_EMPTY_THRESHOLD`) 또는 ② 8초 무입력(`HINT_IDLE_MS`). 화면은 1초마다 확인 |
| 추천 쌍 | 가능한 합성을 모두 사본에서 해 보고 점수가 가장 높은 1개. 점수 = 납품 × 10000 + 이번 합성으로 장착되는 부품 수 × 100 + 합성 뒤 남는 합성 쌍 수 × 10. 같으면 칸 순서가 빠른 쪽이라 같은 상태면 항상 같은 쌍 |
| 표시 | 두 칸에 잉크색 바깥선 + 노란 테두리를 반짝이고(동작 줄이기 설정이면 깜빡임 없음), 안내 줄에 이유: 납품까지 이어져요 / 바로 장착돼요 / 다음 합성 자리가 남아요 / 칸이 하나 비어요 |
| 해제 | 화면 어디든 누르면 사라지고 무입력 시간을 다시 셈. 하루 마감(입력 잠금) 중에는 보여 주지 않음 |
| 막힘 | 꽉 찼는데 합성 쌍이 없으면 추천하지 않음(반품으로만 진행) |

**기대 효과(Lab 시뮬레이션, 이전 주문 3종 기준·추천을 항상 따르는 상한)**: 초보식 합성의 막힘 회차 34% → 20%, 주문당 반품 약 1/3. 메인 영업일 주문표(Lv.4·Lv.3 2종 주문일)에서는 다시 측정하지 않았습니다([레벨 디자인 위험 1](../game-design/LEVEL_DESIGN.md)).

**사람 플레이로 볼 것**: 추천을 따르는 비율, '정답 강요'로 느끼는지, 막혔을 때 이유를 설명할 수 있는지.

## 8. 체력 소진 안내 (Lab #263 A안)

Lab [#263](https://github.com/aigemro/dream-bike-garage-lab/issues/263) A안(소진 안내 카드)을 메인 작업대에 다시 만들었습니다. 광고 버튼은 아직 없고, 보상형 광고(#92)를 붙일 때 이 카드에 더합니다. B안(일일 무료 충전)·C안(휴식 전환)은 적용하지 않았습니다.

| 항목 | 내용 |
|---|---|
| 여는 때 | 체력 0이고 무료 상자도 없을 때(`isEnergyEmpty`) 부품 상자 버튼을 누르면. 이때 상자 버튼 문구는 '체력 소진 · 눌러서 회복 안내 보기' |
| 내용 | 오늘 진행이 저장됨, 다음 +1까지 남은 시간(1초마다 갱신), 가득 참까지 남은 시간(`msUntilFullEnergy`), 체력 없이 할 수 있는 일(확정 상자가 있으면 확정 상자, 합성할 쌍이 있으면 합성·합성 3회 무료 상자, 없으면 홈에서 도감·강화) |
| 버튼 | 홈으로(Day 일시정지), 작업대로 돌아가기(합성할 쌍이 없으면 '닫기') |
| 입력 | 카드가 열린 동안 화면 전체를 어두운 막으로 덮어 뒤쪽 보드·버튼 입력을 막음. 합성 추천도 보여 주지 않음 |
| 자동 닫힘 | 카드를 연 채로 체력이 1 회복되면 닫고 '체력이 회복됐어요' 안내 |

## 9. 보상형 광고 체력 충전 (#92)

[#92](https://github.com/aigemro/dream-bike-garage/issues/92) 초안 수치로 적용했습니다. Lab [#263](https://github.com/aigemro/dream-bike-garage-lab/issues/263)·[#275](https://github.com/aigemro/dream-bike-garage-lab/issues/275)의 어댑터 계약·실패 방어를 참고해 메인 구조로 다시 만들었습니다(Lab은 체력 0일 때만 제안했지만 메인은 #92 조건을 따름).

**2026-10-18 변경 — 횟수·간격 제한 없음**: 끝까지 이어서 플레이할 수 있도록 하루 3회·충전 간격 10분 제한을 없앴습니다. 간격을 남기면 체력 0 → 광고 +10 → 1분 안에 다 쓰고 9분 대기라 '계속 충전'이 되지 않기 때문입니다. 충전량이 버려지지 않게 하는 '체력 20 이하일 때만 제안'과 중복 보상 방지는 그대로 둡니다.

### 규칙 (`REWARDED_AD_POLICY`, 수치는 여기서만 바꿈)

| 항목 | 값 |
|---|---|
| 충전량 | 광고 1회 +10 (최대 30을 넘지 않음, 가득 차면 회복 기준 시각을 지금으로) |
| 제안 조건 | 체력 20 이하일 때만. 하루 횟수·충전 간격 제한 없음 |
| 보상 지급 | SDK `userEarnedReward` 이벤트를 받은 순간에만. 닫힘·클릭·노출만으로는 지급하지 않음 |
| 중복 방지 | 광고 요청마다 식별자를 만들고, 마지막으로 보상한 식별자와 같으면 반영하지 않음. 한 요청 안의 중복 이벤트는 어댑터에서도 한 번만 전달 |
| 기록 | `release.adRefill = { count, lastRewardAt, lastRequestId }`. count는 누적 보상 횟수(제한에 쓰지 않음, 기록용). 하루 횟수가 있던 이전 기록(`date` 포함)은 날짜만 버리고 이어서 씀 |

### 흐름

1. 체력 표시(옆에 광고 가능하면 `▶+10` 표식)나 소진 카드에서 체력 카드를 엽니다. 광고 버튼은 체력 20 이하면 '▶ 광고 보고 체력 +10', 넘으면 '체력 20 이하일 때 광고로 충전할 수 있어요'입니다. 제안할 수 있으면 카드를 열 때 광고를 미리 불러옵니다.
2. 버튼을 누르면 Day를 일시정지(`pauseReason: 'ad'`, 광고 시간은 영업 시간에 넣지 않음)하고 소리를 멈춘 뒤 **광고 직전 저장**을 마칩니다. 작업대에는 입력을 막는 '광고를 준비하고 있어요' 막을 띄웁니다.
3. 보상 이벤트가 오면 체력 +10과 충전 기록(`release.adRefill`)을 반영하고 **바로 저장**합니다. 체력과 기록이 같은 저장 항목이라 한 번의 저장으로 함께 기록되고, 광고가 닫히기 전에 앱이 종료돼도 보상이 남습니다.
4. 광고가 끝나면 소리·Day를 되돌리고 결과를 알려 줍니다(보상 배너 / 끝까지 보지 않음 / 불러오기 실패). 광고 중 앱 전환 이벤트로 Day가 재개되지 않게 막습니다.
5. 광고가 끝났다는 신호가 60초 동안 없으면 막에 '돌아가기' 버튼을 보여 줍니다(이후 이벤트는 무시하고, 보상은 신호를 받은 경우에만).

## 10. 합성 보너스·확정 상자 (2026-10-18)

이전 '연쇄 보너스'(상자를 열지 않고 이어 합성 3회 = 무료 상자, 5회 = 다음 상자 필수 부품 확정)는 상자를 열 때마다 0으로 끊겨 실제 플레이에서 거의 터지지 않았습니다. 첫 대회(Day 5)까지 한 흐름으로 진행하기 어렵다는 플레이 피드백을 받아 규칙을 바꿨습니다.

### 규칙

| 항목 | 내용 |
|---|---|
| 세는 법 | 합성에 성공할 때마다 `bonusCount` +1. 상자 열기·반품으로 끊기지 않음. 되돌리기는 함께 되돌림 |
| 3번째 | 무료 상자 +1 (`BONUS_FREE_BOX_AT`). 부품 상자 버튼이 체력 대신 먼저 씀 |
| 5번째 | 확정 상자 +1 (`BONUS_PICK_BOX_AT`), 진행은 0으로 |
| 확정 상자 | 하단 '합성 보너스' 칸이 노랗게 바뀌고 '확정 상자 ×n · 눌러서 부품·자리 고르기'. 누르면 부품 종류 카드(이번 주문 요구 레벨·장착 완료 표시) → 놓을 빈칸 선택(놓자마자 합성되는 칸은 초록, 나머지 빈칸은 노랑) → Lv.1(`PICK_BOX_LEVEL`) 배치 |
| 비용·취소 | 체력을 쓰지 않음. 카드에서 '나중에 쓰기', 칸 고르는 중 '× 배치 취소'로 상자를 남긴 채 그만둠. 놓은 뒤에는 ↶ 되돌리기로 무를 수 있음(납품이 확정되면 불가) |
| 보관 | 남은 무료·확정 상자는 Day를 넘어 유지되고 저장됨 |
| 이전 저장 | `combo`·`guarantees`가 있는 저장은 진행 0, 받아 둔 필수 부품 확정 수만큼 확정 상자로 옮김 |

이전 '필수 부품 확정'(다음 상자에서 미장착 부품 보장)은 확정 상자로 대체해 없앴습니다. 미장착 부품이 4번 연속 안 나오면 보장하는 규칙(`MISS_LIMIT`)은 그대로입니다.

**한계**: 보너스만으로는 첫 대회까지 한 번에 가지 못합니다. 체력 한 통(30)과 광고 충전(하루 +10 × 3)을 더해도 60이라 약 14가 모자랍니다(10분당 1 회복 기준 약 2시간 대기). 보너스 기준을 더 낮춰도 71 수준이라, '대회까지 한 흐름'을 목표로 하면 체력 총량(최대치·Day 정산 회복·첫 챕터 지원 등) 조정이 함께 필요합니다. 수치 확정은 #77(체력 최대·소모·회복)에서 합니다. 같은 봇에서 작업량(1~5일차 101)당 체력은 0.84 → 0.74로 약 13% 낮아집니다. 레벨 디자인의 체력 추정 비율(`ENERGY_PER_WORK_UNIT` 0.93, Lab 초보 모델·이전 규칙)도 같은 비율이면 약 0.81이 되며, 재측정은 후속으로 남깁니다.

**읽는 법**

- 최대치(c)·회복 속도(d)는 '대회까지 한 흐름'을 만들지 못합니다. 1~5일차 소모(72)가 체력 한 통과 회복량보다 훨씬 커서, 50으로 올려도 광고 없이는 3시간 넘게 기다립니다. (c)는 이후 챕터의 하루 여유만 크게 늘려 '체력 한 통으로 하루'라는 레벨 디자인 긴장감을 없앱니다.
- 정산 회복(b)은 효과가 크지만 모든 Day에 걸리면 연속 플레이 장벽이 무너집니다(+15면 Day 6~15 연속 대기 1,476분 → 149분, 첫 대기가 Day 9). 하루 1회 접속 플레이어에게는 다음 날 이미 가득 차 있어 효과가 없고, 몰아서 하는 플레이어만 빨라집니다.
- (e)는 1챕터 정산에만 걸려 Day 6부터는 현행과 같습니다. 대회를 마치고 Day 6에서 처음 체력 0을 만나 '내일 다시'로 자연스럽게 끊깁니다. (b)를 1챕터로 한정해도 이후 챕터는 (a)와 같아지며, +10은 광고가 있어야 대기 1분, 없으면 21분입니다.

**추천: (e) 첫 대회 전(Day 1~4) 정산 시 체력 가득** — 광고 유무와 관계없이 모두(300회 중 300회) 대기 없이 첫 대회까지 가고, Day 6부터는 현행 수치 그대로라 이후 '한 번 접속 = 하루 영업' 리듬과 경제에 영향이 없습니다.

### 적용: 첫 대회 전 정산 지원 (2026-10-18, #77 기획 확정 전 시험 적용)

| 항목 | 값 · 동작 |
|---|---|
| 규칙 | 1~4일차(`SETTLEMENT_REFILL_LAST_DAY` = 첫 대회 전날)를 정산하면 체력을 최대치로 채우고 회복 기준 시각을 지금으로 옮김(`applySettlementRefill`, `energy-refill.ts`) |
| 연결 | `finishToday`에서 Day가 실제로 정산될 때(`settleDay`의 `settled`)만 부르고, 정산과 같은 저장에 함께 기록. 가득 채우기라 여러 번 불려도 결과가 같음 |
| 안내 | 하루 정산 화면 마지막 문구에 '첫 대회 전까지는 정산하면 알바 체력이 가득 차요!'(1~4일차만) |
| 기존 저장 | Day 5 이후 플레이어는 영향 없음. 1~4일차 진행 중인 플레이어는 다음 정산부터 적용 |
| 테스트 | `tests/energy-refill.test.ts` '첫 대회 전 정산 지원' — 마지막 지원일이 첫 대회 전날과 같은지(대회 주기를 바꾸면 함께 바꾸도록), 구간 판정, 가득 채우기·멱등, 5일차부터 미적용 |

**체력 수치 검토 결과 — 현행 유지**

| 수치 | 현행 | 판단 |
|---|---|---|
| 최대치 `ENERGY_MAX` | 30 | 유지. 40·50은 첫 대회 대기를 4~6시간 남긴 채 Day 6~15 하루 여유만 12 → 22·32로 늘려 '체력 한 통으로 하루' 긴장감이 사라짐 |
| 회복 `ENERGY_RECOVERY_MS` | 10분당 1 | 유지. 1챕터만 5분으로 줄여도 광고 없이 3.5시간 대기 |
| 상자 비용 | 1 | 유지(합성 보너스 개편으로 실제 소모가 이미 약 13% 감소) |
| 광고 충전 `REWARDED_AD_POLICY` | +10 · 20 이하 (하루 3회 · 10분 간격 → 제한 없음) | 충전량·조건 유지, 횟수·간격 제한은 2026-10-18에 없앰(9절). 정산 지원과 겹쳐도 1챕터에서는 거의 쓰이지 않고, Day 6부터 '기다리기 싫으면 광고'로 끝까지 이어 갈 수 있음 |
| 정산 회복 | 없음 → 1~4일차만 가득 | 이번 적용. 모든 Day에 +10·+15를 주면 몰아서 하는 플레이어의 Day 6→15 대기가 1,476분 → 578·149분으로 무너짐 |

함께 정할 것(기획):

- 레벨 디자인 1챕터 서술의 'Day 2에서 처음 체력 0 → 회복 대기·반품·광고를 배움'이 Day 6 이후로 밀립니다. 체력 0 안내 카드·광고 충전 첫 경험을 대회 뒤로 옮겨도 되는지(LEVEL_DESIGN 1·9절 수정).
- 정산 화면에 '첫 대회 전까지는 정산하면 체력이 가득 차요' 같은 안내를 넣을지. 문구만 바뀌어도 등급분류 대상 화면 확정 전에 정해야 합니다.
- 기존 진행 플레이어(Day 5 이후)는 영향이 없습니다.

## 11. 대회일 참가 질문과 참가비 요건 (#107)

대회일(Day 5·10·15…)에 홈의 `RACE GO!`를 누르지 않고 주문 3건을 끝내면 정산 → 다음 영업으로 넘어가며 대회 기회가 사라지던 문제를 고쳤습니다.

| 항목 | 내용 |
|---|---|
| 판정 | `raceEntryStatus(race-progress.ts)` 한 곳에서 `not-race-day` / `completed` / `paid` / `ready` / `coins`를 계산하고, 홈 버튼·대회 화면 진입·정산 질문이 같은 값을 씁니다 (`canEnterRace`는 `ready`·`paid`만 참) |
| 정산 질문 | 대회일 정산에서 봉투를 열고 나면 다음 영업 카드 대신 'RACE DAY · 대회에 참가할까요?' 질문을 띄웁니다. `참가하기` → 대회 화면, `참가 안 함` → 기존 다음 영업 카드 |
| 참가비 부족 | 보유 코인이 참가비(500)보다 적으면 질문의 참가 버튼을 `참가 불가`로 잠그고 '참가비가 부족해 오늘은 참가할 수 없어요'를 보여 줍니다. 홈 대회 버튼도 `참가비 부족`으로 바뀌고 누르면 안내 토스트만 띄웁니다. 참가비를 이미 낸 날(`raceEntryDay === 오늘`)은 코인과 관계없이 참가할 수 있습니다 |
| 대회 뒤 | 정산 질문에서 참가한 대회는 결과 정산 뒤 다음 영업일을 준비(`beginNextDay`)하고 홈으로 돌아갑니다. 대회 화면에서 `← 홈`으로 나오면 정산 화면으로 돌아가되 봉투 개봉 연출은 건너뜁니다(`alreadyOpened`), 낸 참가비는 유지됩니다 |
| 테스트 | `tests/race-progress.test.ts` '대회 참가 가능 판정(#107)' |

한계: 정산 질문에서 대회 화면으로 간 뒤 앱을 닫으면 다음 진입 때 저장 복구가 정산 완료 Day를 다음 Day 준비로 열어(5절) 그날 대회는 지나갑니다. 복구 시 대회일 정산 상태를 유지할지는 후속으로 남깁니다.
