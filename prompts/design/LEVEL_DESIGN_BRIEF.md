## 1. 게임 한 줄 요약과 루프

**오늘부터 자전거 부자** — 자전거샵 알바가 고객 주문에 맞춰 부품을 머지해 자전거를 조립·납품하고, 급여로 자신의 드림 바이크와 컬렉션을 키우는 캐주얼 머지 웹게임 (Phaser 3 + TS, 앱인토스 2026-11 출시 목표, 2인 팀).

핵심 루프: 고객 주문 → 부품 상자 열기 → 같은 부품 2개 합성 → 요구 레벨 도달 시 자동 장착 → 4종 장착 = 납품·급여 → 자전거 이해도 ↑ → 도감 등록 → 급여로 부품 제작(보유) → 강화(성장) → 5일마다 대회 → 다음 주문

## 2. 바꿀 수 없는 것 (현재 구현·결정 사항)

### 2.1 작업대(머지 코어 E안) — `src/domain/merge-workbench.ts`
- 보드 6×7 = 42칸. 부품 4종: 프레임 `frame`, 휠셋 `wheel`, 구동계 `drivetrain`, 핸들바 `handlebar`. 레벨 Lv.1~4.
- 부품은 옮길 수 없음. 상하좌우로 맞닿은 같은 종류·같은 레벨 2개를 합성 → 한 단계 위 1개.
- 상자 1개 = 알바 체력 1 소모 → 보드 가운데에서 바깥 순서의 다음 빈칸에 부품 1개 입고.
- 입고 확률: Lv.1 80% · Lv.2 20%. 70%는 아직 장착하지 않은 부품 종류에서 뽑고, 미장착 종류가 4번 연속 안 나오면 다음에 보장.
- 장착: 현재 주문의 부품별 요구 레벨 **이상**인 부품이 보드에 생기면 즉시 자동 장착(여러 개면 가장 낮은 레벨). 4종 모두 장착되면 그 자리에서 납품 확정(되돌리기 불가), 다음 주문으로 넘어가고 남은 부품은 보드에 이월.
- 연쇄 보너스: 상자를 열지 않고 이어서 합성 3회 → 무료 상자 1, 5회 → 다음 상자에서 미장착 부품 확정.
- 반품(부품 버리기, 체력 환급 없음), 직전 1회 되돌리기.
- 알바 체력: 최대 30, 상자당 1, 실제 10분당 1 회복. 체력 0이면 상자를 못 열고 회복을 기다림(보상형 광고 충전 +10은 후속 #73).
- 시작 보드: 프레임 Lv.1 ×3, 휠셋 Lv.1 ×3, 구동계 Lv.1, 핸들바 Lv.1 → 첫 주문(프레임2·휠2·구동1·핸들1)을 지급 부품만으로 끝낼 수 있음.
- **주문은 순차·강제**: 플레이어가 주문을 고르지 않고, 정해진 순서의 다음 주문이 자동으로 옵니다. 주문 순번은 누적 카운터(`state.order`)이며 `orderIndexOf(order, orders)`로 주문 목록 위치를 구합니다(현재는 길이 3 목록을 모듈로 순환).

### 2.2 Day 세션 — `src/domain/day-session.ts` (#77 C안)
- **주문 3건 납품 = 영업 1일차 종료 → 정산 → 다음 영업일**. 시간 제한 없음(영업 시간은 정산 표시용 기록만).
- 체력이 떨어지면 같은 Day를 다음 접속에 이어서 함. 작업대 보드·부품은 Day를 넘어 이월됨.
- 따라서 누적 주문 순번 n(0부터)과 Day의 관계: **Day d = 주문 순번 3(d−1) ~ 3(d−1)+2**.

### 2.3 메타 루프 — `src/game/release/meta-progress.ts`
- 납품 1회 = 대상 자전거 **이해도 +50%** → 100%(납품 2회)에 **도감 등록**(제작 가능). 같은 자전거를 더 납품해도 변화 없음(급여만).
- 등록 자전거는 Garage에서 **부품 4종을 코인으로 하나씩 제작**해 완성(보유): 프레임 400 · 휠셋 300 · 구동계 200 · 핸들바 100 = **1,000코인/대** (현재 등급 무관 고정).
- 보유 자전거는 **강화**: 스탯 3종(성능·스타일·희귀도) 각 Lv.1~4, 비용 **350 × 현재 레벨** (한 대 풀강 = 3 × (350+700+1050) = 6,300). 스탯 합계 7 이상 = 고급 단계, 10 이상 = 드림 단계.
- 홈 NEXT GOAL 우선순위: 등록·미완성 자전거 제작 → 미등록 자전거의 주문 납품 → 보유 자전거 강화 → 반복.
- 시작 보유 1대: `dream-road`(나의 드림 로드바이크, 중급). 시작 코인 0.

### 2.4 대회 — `src/game/release/race-progress.ts`

## 4. 설계 대상 (이번에 정할 것)

메인에 들어갈 레벨 디자인은 **"영업 N일차 주문표"**입니다. 주문은 순차·강제이므로 Day d의 3건을 설계자가 직접 정하는 것이 곧 레벨 디자인입니다. 다음을 모두 포함해 제안하세요.

1. **챕터(단계) 구조**: 전체 게임을 몇 개 구간으로 나누고, 각 구간의 목표·새로 배우는 규칙·공개되는 것(카테고리·등급·Lv.4·대회 등)을 정의. 8/6 회의의 직급 아이디어(알바생 → 견습공 → 기술자 → 마스터)와 연결해도 좋음(화면 변경 없이 '구간 이름'으로만).
2. **주문 정의 20종+**: 일반 자전거 20대 각각에 주문 1개 이상(id, 표시 이름 "~용 ~" 식의 손님 맥락, bikeId, 렌더 카테고리, 등급, 요구 레벨 4종, 보상). 같은 자전거의 두 번째 주문은 같은 정의를 다시 써도 되고 변형(레벨↑·보상↑)을 둬도 됨.
3. **Day별 주문표**: Day 1부터 설계가 끝나는 Day N까지, 하루 3슬롯에 주문 id 배치. Day마다 작업량 합·예상 체력(0.93×작업량)·대회일 여부·설계 의도 한 줄. 원칙:
   - Day 1 슬롯 0은 반드시 `urban-road` 2/2/1/1(시작 보드와 결합).
   - 모든 일반 자전거 20대가 2회 이상 납품되어 **전부 도감 등록**되도록.
   - 새 규칙·새 카테고리·Lv.4 같은 어려움은 한 번에 하나씩. 하루 작업량 합은 체력 한 통(30)으로 끝나게(대략 ≤ 27~28 작업량) 하되, 의도된 '바쁜 날'은 명시. 하루 마지막 슬롯은 상대적으로 쉽게.
   - 대회일(Day 5·10·15…)과 그 전날의 리듬을 고려(참가비 500 확보, 대회 전 강화 유도 등).
4. **설계 끝 이후(엔드게임) 규칙**: Day N 이후 어떤 구간을 반복할지(`repeatFrom`: 설계 Day 중 어느 Day부터 끝까지를 무한 반복). 반복 구간은 보상·난이도가 후반 수준이어야 하며 튜토리얼 주문으로 돌아가면 안 됨.
5. **드림 등급 3대 해금 규칙**: dream-machine(로드)·expedition-gravel(그래블)·dream-mini(미니벨로). 카탈로그 힌트는 '드림 등급 승급 보상'. 예) 같은 카테고리 보유 자전거 1대를 드림 단계(스탯 합 10)로 올리면 도감 등록. 구현이 단순한 규칙을 권장(현재 모듈에 작은 함수 추가 수준).
6. **경제 곡선**: 챕터별 예상 수입(주문 보상 합), 사용처(제작·강화·참가비), Day 10·20·30 시점 코인 잔고 추정. 코인 적체가 크면 **사용처 조정 제안**(예: 등급별 제작 비용 배수 입문 1× · 중급 1.5× · 고급 2× 같은 단순 배수, 강화 비용은 유지)과 그 근거. 숫자는 단순 산수로 보여 주세요.
7. **체력 리듬**: 챕터별 하루 체력 추정, 한 통으로 하루를 못 마치는 날이 어디인지, 그것이 의도인지.
8. **첫날(튜토리얼) 흐름**: Day 1의 3건이 가르치는 순서(합성 → 상자 → Lv.3 → …). 안내 화면은 바꾸지 않음(등급분류 화면 고정).
9. **대회 연결**: 출시는 현행 수치 유지 전제. 레벨 디자인 상 Day 5·10·15 대회에서 플레이어가 어디쯤 성장해 있을지(성능 레벨 추정)와, 출시 후 등급 리그를 어느 Day부터 붙이면 좋을지 한 단락.
10. **열린 결정**: 기획자가 확정해야 할 항목 목록(수치·명칭·규칙), 그리고 위험.

### 설계 제약(구현 관점)
- 화면·안내 화면은 바꾸지 않음(앱인토스 등급분류용 화면 고정). 데이터와 순수 규칙(`src/data`, `src/domain`, `meta-progress`)만 바뀜.
- 하루 주문 수 3, 체력 30/1/10분, 입고 확률, 이해도 50%/회, 강화 비용은 바꾸지 않음(#77에서 '현행 유지' 권고).
- 요구 레벨은 1~4. Lv.4는 작업량 8이라 한 주문에 1개까지만 권장.
- 주문 이름은 한국어, 손님 맥락이 드러나게(예: "통학용 어반 로드", "배달용 카고 미니벨로"). 실제 브랜드 금지.

## 5. 출력 형식
아래 JSON 스키마(StructuredOutput)를 채우세요. 설명·근거는 `rationale` 필드에 한국어로. 숫자는 정수.
- `chapters[]`: `{ id, name, rankName, dayFrom, dayTo, goal, teaches[], unlocks[] }`
- `orders[]`: `{ id, bikeId, name, category('road'|'mtb'|'gravel'|'minivelo'|'city'), grade('입문'|'중급'|'고급'), levels: { frame, wheel, drivetrain, handlebar }, reward, note }`
- `schedule[]`: `{ day, slots: [orderId, orderId, orderId], workUnits, energyEstimate, raceDay(boolean), intent }`
- `repeatFromDay`: 정수 (이 Day부터 마지막 Day까지를 반복)
- `dreamBikeRule`: `{ summary, perBike: [{ bikeId, condition }] }`
- `economy`: `{ craftCostMultiplierByGrade: { 입문, 중급, 고급, 드림 }, incomeByChapter: [{ chapterId, orders, income }], sinks: [{ name, amount, when }], coinsAtDay: { d10, d20, d30 }, notes }`
- `energy`: `{ perOrderAvg, perDayByChapter: [{ chapterId, avg, max }], heavyDays: [day...], notes }`
- `tutorialDay1`: 문자열
- `race`: `{ expectedPerformanceLevelAtDay: { d5, d10, d15 }, notes, postLaunchLeagueFromDay }`
- `openDecisions[]`: 문자열, `risks[]`: 문자열, `rationale`: 문자열(핵심 판단 5~10문장)
